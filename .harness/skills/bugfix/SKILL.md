# Bugfix Skill

## 适用场景

- 修复线上 bug、用户反馈的问题或回归问题。
- 修复失败测试、CI 失败或环境中可复现的错误。
- 修复边界条件、错误处理、数据一致性或权限判断缺陷。
- 排查“以前可用，现在不可用”的行为变化。

## 必须读取

1. `AGENTS.md`
2. `.harness/workflows/bugfix.md`
3. `.harness/rules/coding-rules.md`
4. `.harness/rules/testing-rules.md`
5. 与失败行为相关的 `docs/product/`、`docs/domain/` 或 `docs/architecture/`
6. 失败测试、日志、用户复现步骤或相关代码路径

## 工作流程

1. 固定问题边界：写清楚预期行为、实际行为、触发输入和受影响范围。
2. 复现失败：优先运行最小命令或最小测试；无法复现时说明缺失条件。
3. 定位根因：沿输入、状态变化、持久化、副作用和输出追踪。
4. 评估影响：检查相邻路径、兼容性、权限、数据和外部系统。
5. 做最小修复：只改导致失败的必要代码，不混入重构。
6. 补回归测试：测试名表达旧失败模式，断言能在旧实现中失败。
7. 运行验证：先跑聚焦测试，再按风险运行更大范围验证。
8. 总结结果：说明根因、修复点、验证命令和剩余风险。

## 根因分析清单

- 输入是否被错误解析、截断、默认化或信任。
- 状态是否在并发、缓存、事务或重试下不一致。
- 权限、租户、资源归属或数据范围是否遗漏。
- 时间、时区、排序、分页、空值、重复值是否导致边界错误。
- 外部服务失败、超时、返回格式变化是否被正确处理。
- 前后端契约、schema、错误码或配置是否不一致。

## 修复边界

- 不顺手重构。
- 不用扩大行为绕过问题。
- 不删除失败测试来让验证通过。
- 不新增依赖，除非根因无法用现有能力合理修复。
- 不修改产品预期；如果预期不清楚，先更新或确认需求文档。

## 验证命令

按范围选择：

```bash
make test
make check
```

Python 项目可聚焦运行：

```bash
uv run pytest path/to/test_file.py -q
```

前端项目可聚焦运行：

```bash
pnpm run test
```
