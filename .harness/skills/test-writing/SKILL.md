# Test Writing Skill

## 适用场景

- bugfix 后补回归测试。
- 新功能、新 API、新 service 或新 UI 行为需要测试。
- 固化权限、校验、错误处理、数据转换或状态机规则。
- 为 RAG、workflow、multi-agent 工具调用和失败路径补覆盖。
- 修复 flaky test、错误 mock、过度依赖实现细节的测试。

## 必须读取

1. `AGENTS.md`
2. `.harness/rules/testing-rules.md`
3. `.harness/rules/coding-rules.md`
4. 与行为相关的产品、领域或架构文档
5. 最接近的现有测试和测试配置
6. 被测代码路径和失败样例

## 测试选择

- 单元测试：业务规则、纯函数、权限判断、状态转移、错误映射。
- API/集成测试：HTTP 契约、依赖注入、数据库访问、外部客户端边界。
- 前端测试：用户操作、状态渲染、表单、错误反馈、导航。
- 回归测试：固定旧失败模式，确保 bug 不再出现。
- 安全测试：越权访问、恶意输入、敏感信息泄露、路径或注入风险。
- RAG/Agent 测试：空结果、工具失败、权限过滤、来源归因、停止条件。

## 工作步骤

1. 识别被保护的行为，不从实现细节出发。
2. 找到项目已有测试风格、fixture、mock 和断言模式。
3. 先写能暴露问题或保护新行为的断言。
4. 覆盖成功路径、失败路径、边界条件和权限条件。
5. 控制外部 I/O、时间、随机数、网络和第三方服务。
6. 运行聚焦测试，失败后修正测试或实现。
7. 扩大验证范围，确认没有破坏相邻行为。

## 质量门禁

- 测试名表达业务行为或失败模式。
- 断言验证结果，不只验证函数被调用。
- Mock 只隔离外部边界，不 mock 被测模块内部实现。
- 测试数据最小、可读，不使用真实密钥或生产数据。
- 测试不依赖执行顺序、共享脏状态或本机环境。
- 删除或放宽测试必须说明等价覆盖。

## 验证命令

```bash
make test
make check
```

可聚焦运行：

```bash
uv run pytest tests/path_to_test.py -q
pnpm run test
```
