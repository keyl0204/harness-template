# Docs Sync Skill

## 适用场景

- 用户可见行为、验收标准、业务规则或状态流转变化。
- API、schema、数据库、集成、部署或配置方式变化。
- Harness 工作流、Agent、Skill、规则或验证入口变化。
- README、AGENTS、运维手册或架构文档中的命令和路径需要同步。
- 审查发现文档和实现不一致。

## 必须读取

1. `AGENTS.md`
2. `.harness/workflows/docs-update.md`
3. `.harness/rules/doc-boundary-rules.md`
4. 与变更相关的源代码、配置、测试或工作流
5. 可能受影响的 `docs/`、`.harness/`、`README.md` 或 `AGENTS.md`

## 文档归属规则

- `.harness/`：AI 如何协作，包括 Agent、Skills、规则、工作流、任务状态。
- `docs/product/`：用户目标、用户故事、验收标准、路线图。
- `docs/domain/`：术语、业务规则、权限模型、状态机。
- `docs/architecture/`：模块边界、API 规范、数据库、集成和系统设计。
- `docs/operations/`：本地开发、部署、回滚、排障和运维流程。
- `README.md`：人类读者的项目入口、快速开始和常用命令。
- `AGENTS.md`：Codex 的项目入口、文档路由和完成标准。

## 工作流程

1. 识别触发文档更新的具体变更。
2. 判断变更属于项目事实、工程配置还是 Harness 协作规则。
3. 找到最小相关文档，不做全仓文案润色。
4. 更新文档中的命令、路径、项目类型、依赖、角色或验证入口。
5. 检查引用文件是否存在，避免失效链接和旧名称。
6. 对业务、架构或运维变化补充“为什么”和“如何验证”，不要只写结果。
7. 汇总文档更新和未覆盖区域。

## 质量门禁

- 文档不能引入未实现行为。
- 文档不能把临时任务计划写成长期规则。
- `.harness/` 不写具体业务需求；`docs/` 不写 AI 角色分工。
- 命令示例必须和当前包管理器、项目类型、路径一致。
- 旧项目类型、旧命令、旧依赖和旧模型名称必须同步清理。

```text
- ...

- ...

未覆盖风险：
- ...
```
