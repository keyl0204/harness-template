# 安全规则

## 安全基线

1. 权限模型必须表达为 `actor`、`resource`、`action` 和 `condition`。
2. 所有跨信任边界输入必须校验，包括 HTTP、CLI、文件、消息队列、Webhook、LLM 输出和第三方回调。
3. 不记录密钥、令牌、原始凭据、完整认证头、个人敏感信息或供应商请求原文。
4. API 响应不暴露内部异常、文件路径、堆栈、环境变量或调试上下文。
5. 服务端必须重新校验权限；前端隐藏按钮不等于授权。
6. 安全相关默认值必须保守，失败时拒绝而不是放行。

## 权限和租户

1. 每个受保护操作必须明确：
   - actor：谁在操作。
   - resource：操作什么资源。
   - action：执行什么动作。
   - condition：租户、归属、状态、角色、时间、额度等条件。
2. 列表、详情、导出、批量操作和搜索都必须做数据范围过滤。
3. 管理员、破坏性操作、账单、密钥管理必须有额外确认或审计。
4. 权限变更必须补越权访问测试。

## 输入输出安全

1. 文件路径必须规范化并限制在允许目录内，防止路径穿越。
2. 用户可控值不得拼接 shell 命令；确需执行命令时使用参数数组和白名单。
3. SQL、向量检索过滤条件、搜索 DSL 和模板渲染必须使用参数化或结构化 API。
4. 上传文件必须限制大小、类型、扩展名、内容嗅探和存储位置。
5. 输出到 HTML、Markdown、日志或 prompt 的用户内容必须按目标上下文转义或隔离。

## 密钥和配置

1. 密钥只从受控配置入口读取，不写入代码、文档、测试快照或日志。
2. 令牌、Webhook secret、API key 和数据库 URL 必须支持轮换。
3. 示例配置使用占位值，不使用真实账号、真实域名凭据或内部地址。
4. 错误报告和埋点必须脱敏。

## AI/RAG/workflow/multi-agent 安全

1. Prompt 中不得放入不必要的密钥、凭据、完整用户隐私或内部策略。
2. RAG 必须保留来源和访问控制过滤，不允许越权检索上下文。
3. LLM 输出不能直接作为权限决策、SQL、shell、文件路径或工具参数使用。
4. 工具调用必须有 allowlist、参数 schema、超时和审计记录。
5. multi-agent handoff 必须限制可传递的敏感上下文。
6. workflow 节点重试必须避免重复扣费、重复发送、重复写入和重复执行破坏性动作。

## 触发安全审查的场景

- 认证、授权、租户隔离或权限模型变更。
- 文件、网络、shell、Webhook、第三方 API 或浏览器自动化操作。
- 密钥处理、日志、监控、导出、上传下载。
- 支付、账单、管理员、删除、批量修改或不可逆操作。
- RAG 检索、Agent 工具调用、工作流执行、代码执行或 prompt 拼接。

## 安全交付要求

1. 列出新增或变化的信任边界。
2. 说明权限校验点和失败行为。
3. 补充必要的越权、注入、路径穿越或敏感信息泄露测试。
4. 无法自动化验证时，写明人工检查步骤和剩余风险。
