# 编码规则

## 要求

1. 优先沿用项目现有模式，而不是新增抽象。
2. 改动范围必须贴合当前任务。
3. 避免无关格式化改动。
4. 只有在必要且有充分理由时才新增依赖。
5. 错误必须清晰且可测试。
6. 除非任务要求，否则保持公开契约不变。

## Python

- 新增代码使用带类型的函数签名。
- 如果存在 service 层，不要把复杂业务逻辑写进 API router。
- 优先使用结构化解析 API，而不是临时字符串处理。

## 前端

- 复用现有组件和状态管理模式。
- 在适用场景下补齐 loading、empty、error、success 状态。
- 除非本地规范允许，否则避免 inline style。
